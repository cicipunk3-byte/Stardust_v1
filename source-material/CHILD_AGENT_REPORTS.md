# Child Agent Reports

Standing convention: completion (or blocked) reports from child agents run
in this workspace, preserved here because their reasoning and flagging
judgment exists only in the orchestrating conversation, not on disk. See
`HANDOFF.md`'s Communication section and `AGENTS.md`'s end-of-session steps
for when an agent should add one.

Not every run gets an entry. This file is for the reasoning behind a report
- why an agent stopped where it stopped, what it judged worth cici's direct
attention rather than a log entry - when that reasoning is more than the
terse `JOURNAL.md` template captures. Routine work fully captured by a
`JOURNAL.md` entry doesn't need a duplicate here.

Entries are append-only, like `JOURNAL.md`, not pruned or consolidated like
`MEMORY.md`. The point is preserving reasoning that exists nowhere else;
compressing it would defeat that.

These are the agents' own words, lightly formatted, one section per agent
per task: a level-two heading naming the agent and the batch or task range,
followed by why it stopped where it stopped and what it flagged for direct
attention (see the two entries below for the pattern). Their claims carry
the same standard as everything else here: what an agent reported is not
the same as what was verified. Check a claim against the source material or
the log before recording it - don't transcribe a report unchecked just
because an agent said it about itself.

Full conversation transcripts are not included. There is no tool for one
agent to export another's conversation; that has to be done by hand from
each conversation if it is ever wanted. This disclaimer stays regardless of
how the rest of this preamble changes - without it, this file misrepresents
partial preservation as complete.

The first two entries below predate this convention; they were the reports
that prompted writing it down.
