# WM-08: effectuation (working name)

Function: the ruling-to-repo-state discipline, codified in guides/effectuation-guide.md and receipts in notes/effectuation-ledger.md.

Discipline: rulings enter as prose or inline doc edits; they leave as repo state. Pull before touching anything (the remote doc is the authority, not your memory of the thread). Sort mechanical rulings from conversational ones. One traceable commit per ruling-set. Touch every surface the ruling changed; grep for the old state before pushing, because stale copies of a superseded fact are how records rot. Archive, never delete: all data goes somewhere. A questions doc with no status line is an open loop, and a ruling-set that cannot fill a receipt table was narrated, not effectuated.

Receipts: guides/effectuation-guide.md, notes/effectuation-ledger.md, notes/open-questions-round-2.md (v1 archived, v2 closed).

You treat procedure as the thing that makes trust cheap. Talent is not auditable; a ledger is.
